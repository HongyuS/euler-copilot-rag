# 日志解析方案说明

本方案基于**多进程+任务队列**架构实现日志解析任务的分布式执行：日志解析任务触发后，由任务队列统一调度并为每个任务创建独立进程；进程生命周期内划分为四个核心状态——等待解析、解析中（包含细分阶段）、解析完成、解析失败，实现任务状态的精细化管控。

日志异常识别逻辑封装为独立类（LogAnomalyDetector），核心流程及优化策略如下：
1. 日志读取与切分：读取指定目录下的目标日志文件，根据文件路径特征匹配预设的专属切分规则；若路径无匹配规则，则默认按行切分日志内容。
2. 日志模板生成与去重：基于Drain3等日志模板挖掘算法，将原始日志转换为结构化日志模板，并对生成的模板进行去重处理，消除冗余。
3. 多模型向量表征：采用多协程/多线程并行方式，加载多个Embedding模型对日志模板进行向量化；通过多模型特征融合，提升日志语义信息的保留度。
4. 维度规约：基于主成分分析（PCA）等降维算法，对高维日志向量进行降维，降低后续计算复杂度，同时保留核心特征。
5. 离群点初筛：使用DBSCAN密度聚类算法对降维后的向量进行聚类，自动识别并提取聚类外的离群点（疑似异常模板）；聚类参数（如邻域半径、最小点数）可通过随机搜索、遗传算法等智能寻优方法选取最优值。
6. 异常模板二次聚类：对初筛得到的离群点，采用K-Means算法进行二次聚类，进一步提纯异常日志模板集合。
7. 异常候选集扩充：基于预设的异常词表，对二次聚类后的异常模板进行语义匹配，扩充异常日志候选集。
8. 分数筛选：结合异常词表匹配度与情感分析模型，为候选集中的日志模板计算异常评分，筛选出评分≥50分的模板。
9. 大模型精准过滤：将高分候选模板送入大模型进行语义级异常判定，确定最终的核心异常日志模板库。
10. 原始日志异常匹配与存储：对原始日志进行向量化后，基于FAISS等高性能向量搜索引擎，匹配异常模板库中Top-K最相似的模板；若任一匹配结果的相似度≥80分，则判定该原始日志为异常日志，并将异常日志及其上下文信息持久化存储至本地文件，供后续溯源分析。

---

### 总结
1. 架构层面：核心是**多进程+任务队列**的分布式设计，配合进程四状态管理，实现日志解析任务的可控执行；
2. 算法层面：异常识别流程采用“模板化→向量化→降维→双层聚类→多层筛选”的递进式逻辑，通过多模型Embedding、智能参数寻优提升识别精度；
3. 落地层面：最终通过向量匹配实现原始日志的异常判定，并留存上下文数据，保障分析可追溯。
